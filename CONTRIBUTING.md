# Contributing Guidelines

Thank you for your interest in contributing to this project! To ensure a smooth and efficient workflow, please follow the guidelines below.

## 1. Issue Assignment

- **Ask First**: If you want to work on an issue, please ask to be assigned to the ticket first before starting your work.
- **First Come, First Serve**: Tickets are assigned on a First Come, First Serve basis.
- **48-Hour Rule**: If the assigned person does not reply or show progress within 48 hours, the ticket will be reassigned to the next person in the queue.

## 2. Pull Requests

- **Rebase Your Branch**: Always rebase your Pull Request against the main branch before it is marked as ready for review or ready to merge.
- **Proof of Work**: Attach screenshots or screen recordings to your Pull Request description to visually demonstrate that the bug has been fixed or the new feature is working as intended.
- **Self-Review**: Please perform a thorough self-review of your code before requesting a review from maintainers.
  - *Note on AI Code Assistants*: If you use AI tools to help write your code, ensure you review their output carefully. Remove any unnecessary, verbose, or redundant comments they may have added. Keep your code clean.
- **Requesting Reviews**: Notifications are turned off by default. To ensure your Pull Request gets noticed, you MUST explicitly add the repository owner (`@jammutkarsh`) as a Reviewer in the GitHub UI. This triggers their [PR Pulse](https://chromewebstore.google.com/detail/pr-pulse-github-pull-requ/ffmlmohnpbpplgcmkjlojmbaaeephblg) extension.

## 3. Coding Standards

We have strict coding standards to maintain the quality of the codebase. Please refer to our [Agent Coding Guidelines](.agents/AGENTS.md) for detailed rules on:

- Testing strategies (e.g., using table-driven tests)
- Documentation and minimal commenting
- Naming conventions
- Code structure and best practices (error wrapping, context propagation, etc.)

## 4. Getting Started

1. Fork the repository.
2. Clone your fork locally.
3. Create a new branch for your feature or bugfix.
4. Make your changes adhering to the guidelines above.
5. Push your changes and open a Pull Request!
